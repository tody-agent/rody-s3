# Hỗ Trợ Gia Tốc Kế GY-6500 (MPU-6500) & GY-9250 (MPU-9250) - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nâng cấp toàn diện firmware Rody S3 và Pet Edition, giao diện chẩn đoán Web, CAD tương tác và tài liệu hướng dẫn để hỗ trợ hoàn hảo module gia tốc kế GY-6500 (MPU-6500) và GY-9250 (MPU-9250 9-DOF) bên cạnh MPU-6050 (GY-521) truyền thống.

**Architecture:** Mở rộng lớp giao tiếp IMU đa chip: Tự động dò tìm địa chỉ I2C (0x68 hoặc 0x69), nhận diện WHO_AM_I đa dạng (0x68 cho MPU6050, 0x70 cho MPU6500, 0x71 cho MPU9250, 0x73 cho MPU9255), kích hoạt I2C Bypass Mode cho chip MPU-9250 để la bàn số AK8963 (0x0C) kết nối trực tiếp vào bus I2C chính, cấu hình bộ lọc gia tốc DLPF (ACCEL_CONFIG_2), và cập nhật hệ thống Web Scanner, Self-Test, Wiring CAD SVG và cẩm nang hướng dẫn.

**Tech Stack:** C++ / Arduino ESP32-S3, PlatformIO, FreeRTOS, I2C Wire, HTML5 / Vanilla JS / SVG, Markdown.

**Spec:** N/A (Feature Extension).

## Global Constraints
- Tương thích ngược 100% với MPU-6050 (GY-521) đang chạy.
- Không thay đổi các chân GPIO đã quy hoạch (SDA=IO8, SCL=IO9).
- Tuân thủ quy định AGENTS.md: không đụng vào các GPIO cấm (19, 20, 26–37, 43, 44, 0, 3, 45, 46).
- Cả hai môi trường `pio run -e rody` và `pio run -e rody-pet` phải biên dịch thành công 0 lỗi.

## Review Focus
1. GY-9250 trả về WHO_AM_I = 0x71 (hoặc 0x73 trên MPU9255), nếu không khai báo sẽ bị reject.
2. Một số mạch GY-6500 / GY-9250 kéo chân AD0 lên VCC (3.3V) thay vì GND, làm địa chỉ nhảy sang 0x69. Phải auto-probe cả 0x68 và 0x69.
3. Chip AK8963 trên MPU-9250 bị ẩn sau I2C master nội bộ, phải bật I2C Bypass mode (0x37 bit 1) để scanner và firmware thấy tại 0x0C.
4. Cấu hình DLPF trên MPU6500/9250 cần thêm thanh ghi REG_ACCEL_CONFIG_2 (0x1D).
5. Web diagnostic tool và Self-test cần hiển thị chính xác tên linh kiện phát hiện được.
